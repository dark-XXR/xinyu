## 实施顺序

1. 用户管理、公告发布、网站基础配置。
2. 独立支付运营页与客服工单闭环。
3. 邀请推广管理页。
4. 权限管理员、内容 CMS、版本集成。
5. 告警事故与数据治理。

## 2026-08-10 验收记录

- 用户、公告、网站设置、支付运营和客服五个页面由 Antigravity CLI 完成，均通过
  `1440x900` 与 `390x844` 浏览器验收，无整页横向溢出和控制台错误。
- 用户冻结会撤销全部活跃会话，已持有的 Access Token 每次请求也会再次检查账户状态。
- 网站配置采用草稿与已发布版本分离；公开 bootstrap 只读取已发布版本。
- 公告公开读取按状态、时间、平台、语言和客户端语义版本范围共同筛选；撤回立即失效。
- 客服工单支持用户会话、管理员队列、公开回复、内部备注、分派、优先级和状态流转；
  客服正文进入加密敏感审计，普通元数据不复制正文。
- 支付页复用已验收的易支付供应商、订单、退款和主动对账能力；回调事件诊断与安全重放
  仍是支付域未完成项，因此支付与财务保持“部分完成”。

## 2026-08-11 验收记录

- `/referrals` 由 Antigravity CLI 完成，覆盖活动草稿、渠道和绑定门槛、动态奖励规则、
  反作弊策略、灰度生效窗口、发布及回滚。
- 新增只读不可变活动版本历史接口；页面只允许选择 `wasPublished=true` 且早于当前版本的
  合法目标，避免管理员猜测版本号。关闭高风险对话框会清空理由和目标。
- 新建表单不预填奖励、次数、阈值或审计理由；数字初值仅使用契约边界，实际运营值由
  管理员保存到后台版本。桌面 `1440x900` 与移动端 `390x844` 均无页面级横向溢出，
  控制台无警告或错误。

所有价格、次数、期限、奖励、阈值、频次和展示内容必须来自可版本化后台数据，
不得写死在 Android 或管理页面业务组件。所有冻结、发布、撤回、退款、补偿、导出、
权限和系统配置变更必须要求审计理由，并进入不可变合规审计。
